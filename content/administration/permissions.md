# 页面权限

## 设置一页的阅读和编辑权限

管理员打开页面的“保护”入口，也可访问 `特殊:保护页面?page=页面标题`。分别设置“允许查看的身份”和“允许编辑的身份”，然后保存。

| 选择 | 效果 |
| --- | --- |
| 管理员 | 仅管理员可执行该项操作 |
| 已有用户组 | 属于选中任意一组即可执行 |
| 所有人 | 该项权限公开；编辑仍需通过登录、封禁等检查 |
| 继承站点 / 命名空间规则 | 删除本页的精确规则，改用上级规则 |
| 不允许任何身份 | 显式拒绝该项操作 |

例如，公开阅读但只有管理员能修改：查看选“所有人”，编辑选“管理员”。内部词条可将两项都设为“管理员”。

阅读限制也作用于接口和嵌入内容。隐藏编辑按钮只改变界面，不会限制编辑权限。拥有保护权限的用户仍可进入设置页恢复规则。

插件生成、没有正文记录的页面也可以按标题保存保护规则。保存不会创建空白词条，以后创建同名词条时规则仍然有效。

## 分配用户组

用户组在权限管理页面分配。普通用户不应通过修改正文取得身份；页面权限判断使用账号实际所属的用户组。

首次安装由向导创建管理员。已有站点需要恢复管理权限时，可在 `LocalSettings.yaml` 配置：

```yaml
wikikernel:
  permissions:
    bootstrap-admins:
      - 你的用户名
```

该配置在启动时提升指定账号的权限，不会降低其他账号权限。

## 其他治理功能

[审核](/docs/plugins/moderation)决定提交何时公开；[滥用过滤器](/docs/plugins/abuse-filter)按规则拦截操作；封禁用于限制用户或 IP。这些机制与页面保护分别生效。

## 访问规则参考

规则模型：**目标 + 动作 → 允许的用户组**，存 `wiki_access_rule`（`target` / `action` / `group_names`）。

| 维度 | 取值 |
| --- | --- |
| 目标 | `*`（全部）｜精确标题（`首页`）｜前缀，以 `*` 结尾（`帮助:*`）｜特殊页（`特殊:日志`，按**规范名**匹配，别名同样生效） |
| 动作 | `read` 查看、`edit` 编辑、`create` 创建、`move` 移动、`protect` 保护、`upload` 上传、`delete` 删除 |
| 允许 | `*` = 所有人（含匿名）｜空 = 无人（禁止）｜多个用户组用 `\|` 分隔（任一即可） |

- **匹配优先级**：精确标题 > 最长前缀 > `*`；命中后不再往下匹配；
- **内置默认值**（没有任何规则命中时）：查看=所有人；编辑 / 创建 / 移动 / 上传=登录用户；
  保护 / 删除=管理员；基础组「用户」对登录用户隐式生效；
- **命名空间 / 配置页的内置默认值**（同样可被规则覆盖）：
  微件（`微件:`）命名空间的编辑 / 创建 / 移动=**小部件编辑者**（管理员不豁免）；
  WikiKernel（`WikiKernel:`）命名空间的编辑 / 创建 / 移动=**管理员**；
  `WikiKernel:Titleblacklist` / `WikiKernel:Titlewhitelist` 的查看=**管理员**
  （无权者按「页面不存在」处理：404，且标题不会出现在列表 / 搜索 / 最近更改里）；
- **网页配置**：`特殊:权限配置`——默认规则（目标 `*`）每个动作一行；可添加 / 覆盖 / 删除任意规则；
  只有管理员 / 行政员能修改（`POST /api/access-rules`、`POST /api/access-rules/delete`，`@RestController`）；
  页面本身也受规则控制（如把查看权限设为「无人」后需要靠 LocalSettings 恢复）；
- **LocalSettings.yaml**：`wikikernel.permissions.rules` 里的规则**每次启动导入**，
  覆盖同一「目标 + 动作」的网页修改（网页新增的其它规则保留）；
- **强制点**（全部经过 `AccessControlService`，方便维护）：
  - 页面：`/wiki/标题`、`?action=history`、`?action=raw`（查看）；`?action=edit` 与保存（编辑 / 创建，无权时显示「查看源代码」并提示）；
  - 特殊页：渲染前按 `特殊:<规范名>` 检查查看权限（403）；
  - 移动 / 保护 / 删除：`特殊:移动页面`、`特殊:保护页面`、`特殊:删除页面` 与 `/api/pages/move`、`/api/pages/protect`、`/api/pages/delete`（需登录 + 对应权限；受保护页面需管理员）；
  - 恢复被删页面：`特殊:已删除页面`（`Special:Undelete`）与 `/api/pages/restore`（**只有管理员 / 行政员**，
    与 MediaWiki 的 `undelete` 权限一致；无权时特殊页只显示提示，页面本体也看不到被删内容）；
  - 列表防泄露：`特殊:全部页面`、`特殊:搜索`、`/api/search`、`/api/pages`、`特殊:最近更改`、`特殊:相关更改`、
    `特殊:链入页面`、`特殊:用户贡献`、`特殊:日志`、`特殊:页面信息` 都会隐藏无权查看的页面（标题也不出现）；
- 旧布尔保护标记 `protectedPage` 仍额外要求管理员。新版保护表单按所选编辑用户组保存规则，允许指定其他身份编辑。

例如，限制帮助命名空间的页面创建权限：

```yaml
wikikernel:
  permissions:
    rules:
      - target: "帮助:*"
        action: create
        groups: "自动确定用户"
```

规则中的 `groups` 使用 `|` 分隔多个身份，`*` 表示所有人，空字符串表示无人。网页配置入口为“特殊:权限配置”。

# 备份与升级

## 备份范围

相对路径以应用工作目录为准。默认部署至少保留：

| 路径 | 内容 |
| --- | --- |
| `LocalSettings.yaml` | 本地配置、数据库连接及密钥 |
| `data/` | SQLite 数据库及插件运行数据 |
| `run/files/` | 上传文件 |
| `plugins/` | 当前使用的插件版本 |
| 当前启动 JAR | 与插件配套的内核版本 |

使用 MariaDB / MySQL 时还要备份数据库。使用对象存储时，另行保留对应存储中的文件。实际路径如有自定义，应按配置备份。

## 创建备份

小站可停止服务后复制上述文件，再启动应用。数据库和上传文件应来自同一备份时间点。在线备份需使用数据库支持的备份方式，避免直接复制正在写入的 SQLite 文件。

至少在独立目录中验证一次恢复：用备份的配置、数据库、文件和配套插件启动，检查词条、历史、图片和登录。测试实例使用单独端口及数据目录。

## 升级

1. 备份当前版本和业务数据，记录使用的插件。
2. 停止应用，替换内核及需要更新的插件 JAR。
3. 检查插件目录，同一插件只保留一个版本。
4. 从原工作目录启动，查看数据库和插件加载日志。
5. 检查页面读取、登录、编辑、文件预览及常用插件。

不要用新发行包覆盖现有 `LocalSettings.yaml` 或数据目录。示例配置用于对照新增选项。

回退时应考虑新版本是否修改了数据库结构；需要恢复数据时，使用升级前的成套备份。
